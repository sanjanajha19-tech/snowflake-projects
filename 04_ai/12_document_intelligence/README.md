# 12 - Document Intelligence (invoices and contracts)

Drop PDFs into a stage and get structured invoice and contract data, with an exceptions queue, entirely in SQL. It uses `AI_PARSE_DOCUMENT` (text and layout), `AI_EXTRACT` (fields and line-item tables) and `AI_CLASSIFY` (to classify unknown files). A stream and a task process new files automatically.

## What it builds (schema `ACCEL_DB.DOC_INTEL`)
| Object | Purpose |
|---|---|
| `DOCS_STAGE` | Internal stage, `ENCRYPTION = (TYPE = 'SNOWFLAKE_SSE')` (required by the AI document functions), `DIRECTORY = (ENABLE = TRUE)` |
| `DOCS_STREAM` | Stream on the stage's directory table. Captures new files. |
| `PROCESS_NEW_DOCUMENTS()` | Refreshes the directory, queues new PDFs, parses them, classifies unknown files, extracts fields and writes the tables below |
| `DOC_PROCESSING_TASK` | Checks every 5 minutes and runs only when the stream has data, so it costs nothing when idle |
| `DOC_FILE_QUEUE` | One row per file: status PENDING / PROCESSED / ERROR |
| `PARSED_DOCUMENTS` | Full text in LAYOUT mode (tables as markdown) plus the raw JSON |
| `INVOICE_HEADER`, `INVOICE_LINES` | Invoice number, invoice date, due date, vendor, vendor GSTIN, buyer, PO, subtotal, tax, total, and line items |
| `CONTRACTS` | Parties, effective date, term (text and months), end date, auto-renewal, termination clause and notice days, liability cap (text and amount), governing law |
| `INVOICE_EXTRACT_RAW`, `CONTRACT_EXTRACT_RAW` | Raw `AI_EXTRACT` output, for audit and for tuning questions |
| `DOC_EXCEPTIONS_V` | Rows needing review: missing fields, invalid GSTIN, line totals not equal to subtotal, subtotal + tax not equal to total, bad line arithmetic, unusual GST rate, duplicate invoices, uncapped liability, contracts expiring within 120 days, processing errors |

## Prerequisites
- `00_setup` run. `ACCEL_ADMIN` needs `EXECUTE TASK`, which `00_setup` grants.
- AI_PARSE_DOCUMENT, AI_EXTRACT and AI_CLASSIFY available in your region, or cross-region inference enabled.

## Run order
1. `01_stage_and_tables.sql`
2. `02_processing_procedure_and_task.sql`. Creates the procedure and resumes the task.
3. **Upload the PDFs (UI step):** Snowsight > **Data > Databases > ACCEL_DB > DOC_INTEL > Stages > DOCS_STAGE > + Files**. Upload the three invoices with path `invoices` and the two contracts with path `contracts`. The folder prefix sets the document type; files in other folders are classified with `AI_CLASSIFY`. If you use CLI `PUT`, set `AUTO_COMPRESS = FALSE`.
4. `03_upload_and_run.sql`. Refreshes the directory, calls the procedure and shows the results.
5. `04_exceptions_view.sql`

## 5-step demo script
1. Show the empty stage, then upload the five PDFs live in Snowsight.
2. Run `ALTER STAGE DOCS_STAGE REFRESH; CALL PROCESS_NEW_DOCUMENTS();`, or wait for the task. Point out that this needs no model training and no external OCR service.
3. `SELECT * FROM INVOICE_HEADER;` and `INVOICE_LINES` show GSTIN, tax and line items as typed columns.
4. `SELECT * FROM CONTRACTS;` shows effective date, computed end date, notice period and liability cap amount.
5. `SELECT * FROM DOC_EXCEPTIONS_V;`. The Saffron invoice total mismatch and the Riverbend uncapped liability are flagged for AP and Legal review.

## Client value
- AP invoice capture drops from minutes to seconds per document, with arithmetic and GSTIN validation built in. Typical outcome: 60-80% touchless processing.
- Contract key terms (renewal, notice, liability) become queryable, which surfaces renewal and exposure risk across the portfolio.
- No data leaves Snowflake. Results join directly to POs, suppliers and the GL (for example, three-way match against `DEMO.PURCHASE_ORDERS`).

## Notes
- `AI_PARSE_DOCUMENT` returns JSON text, so the procedure wraps it in `PARSE_JSON(TO_VARCHAR(...))`. The same wrapper is used for `AI_EXTRACT` and `AI_CLASSIFY` so the code works whether the function returns an OBJECT or a string.
- `AI_EXTRACT` limits: 125 pages and 100 MB per file. A table question counts as 10 entity questions, out of a maximum of 100.
- Costs: parsing is billed per page and extraction per token. The task's `WHEN SYSTEM$STREAM_HAS_DATA` check keeps the warehouse off when there are no new files. Suspend the task after the demo with `ALTER TASK DOC_PROCESSING_TASK SUSPEND;`.
- The directory table must be refreshed before the stream sees uploads. The procedure refreshes it on every call, and `03_upload_and_run.sql` refreshes it explicitly.
